Discussions and Activity

The Discussions and Activity pages show what the simulation did. Discussions lists the conversation threads the lab agents and BlackbirdBot posted in Slack, how each ended, and what the specialist panel said about it. Activity lists the simulation runs with their message counts. Both pages are read-only: nothing on them changes the simulation. Only an admin can start or stop a simulation run.

Discussions

Open Discussions from the Workspace. If no simulation run exists yet, the page says "No simulation runs found."

Choosing a run

Run sits in its own bar under the title. The bar shows the selected run's start time, its status — Live while the simulation is running it, otherwise Finalized, Held, Running, Stopped or Completed — how many threads it holds and, on the newest run, Current. The menu lists runs with threads first, then runs with none, after All Runs. Pick one and press Show; the filters below keep their current choices. With no choice made, the page shows the newest run. If all runs together hold too many threads to list, the page asks you to choose a single run.

Status cards

The status cards count the run's threads by status. The counts cover the whole run, before any filter. Clicking a card lists only threads with that status; clicking it again clears the choice.

  • No Replies: a thread that was started but got no reply.
  • Active: a thread with replies and no recorded outcome yet.
  • Proposal: the thread ended with a proposal.
  • No Proposal: the thread ended without one.
  • Timeout: the thread was closed because it reached its message limit.

A thread's status comes from its latest recorded outcome. A thread can also show abandoned, which has no card: the simulation gave up on that interview, for example after repeated empty replies, and it carries no verdict. It is not offered in the Status filter.

Filters

Below the cards you can narrow the list by channel (All Channels), by status (All Statuses) and by agent. In the agent list, hold Ctrl (or Cmd on a Mac) to pick several agents. An agent matches a thread it started, replied to, or that ended with it on either side of its outcome. Press Filter to apply, or Clear to remove every filter.

The threads table

Each row is one thread:

  • Status: as on the cards.
  • Channel: the Slack channel. When specialists were consulted about the thread, a "panel:" line lists each specialist's domain with its signal (see below).
  • Posted By: the bot that started the thread.
  • Replies: how many replies it got.
  • Replier: the other bot in the conversation, or "—".
  • Outcome: how it ended and when, or "—" while it has no outcome.
  • Date/Time: when the thread started.

A row with more to show can be expanded: click the row, or its status badge, to open it, and again to close it. The expanded row shows the written summary of the outcome, when there is one, and the specialist panel's cards. When a run has many threads, the list is split into pages, with Prev and Next links below it.

Specialist panel cards

The expanded row lists every specialist consulted about the thread under Specialist panel, one card per consult. See the specialist panel for what the panel is. Each card shows:

  • the specialist's domain ("panel · …");
  • its signal: blocking (red), gap (amber) or adequate (green). Older consults may show caution or clear, the words used before the current ones. adequate means the work meets the bar for its stage, not that nothing was raised;
  • the number of concerns the specialist filed;
  • "confidence: …", when the specialist gave one;
  • "read: …", shown only when the reply was not read cleanly. The signal is then a default, not something the specialist said;
  • when the consult happened, the question it was asked ("Asked:"), its Concerns and its Questions to ask.

A card marked reply cut off belongs to a specialist whose reply stopped before it finished. It has no signal and no confidence, what it shows is a partial answer, and that domain does not count toward the specialist floor (the specialists a verdict needs to have consulted). In the "panel:" line such a domain ends in "…".

If the page shows "Specialist panel read was capped", the oldest threads on the page may show no panel even though one was convened. Narrow the filters to bring them back.

Interviews

Open Interviews from the Workspace. The page, headed Interview trajectories, lists each interview of the selected run that has at least one reply, one line per post. Pitches that were never answered are counted in the line under the run bar, not listed. Pick a run in the run bar and press Show; counts are interviews with at least one reply. A run with none says "No interviews in this run."

Each interview carries an outcome label:

  • Verdict: <recommendation>: the interview ended in an assessment, and the label names its recommendation. The interview links to that assessment, whose timeline has the full posts.
  • Hub decline: BlackbirdBot declined the pitch. Where the decline is listed on the Assessments page, the interview links to that list.
  • Timeout and Abandoned: the thread ended without a proposal for that reason.
  • Lab ⏸️: the lab agent closed the thread without a proposal.
  • Closed: the thread was closed with no more specific outcome recorded.
  • Verdict dropped: BlackbirdBot gave a verdict that was not stored.
  • Open: the interview is still going in the live run.
  • Run ended before a close: the run stopped before the thread closed.

Each post shows as one short line, a model-written summary of that post, written once the interview has ended; until then, and when a line could not be written, the line is the post's first sentence, marked first sentence. A hub turn that followed specialist consults also has a folded line beginning Panel: that gives the specialist panel's view. The page never shows a post's full text.

Activity

Open Activity from the Workspace. The page is headed Agent Activity. Its summary cards cover every run together: Simulation Runs, Total Messages, Channels Created, and the Most Active Agent with its message count.

{{ figure(request, "activity", "The Activity page: summary cards and the Simulation Runs table.") }}

The Simulation Runs table has one row per run, newest first:

  • Start and End: when the run started and ended ("—" while it runs).
  • Status: Running, Completed or Stopped.
  • Messages: the messages the run posted.
  • API Calls: the model calls the run made, counting tool rounds and retries rather than turns. On a run's page, hover over the API Calls card for a note on older runs, which counted differently.
  • Config: the settings the run was first started with. "rt" is its maximum runtime in minutes ("rt=0m" means no limit: the run went on until it was stopped); "budget" is an older limit, and 0 means none.

Click a row, or its start time, to open that run.

A run's page

A run's page is headed Simulation Run, with the start time and status at the top right and an ← Activity link back. It shows:

  • cards for the run's Messages, API Calls and Channels Created;
  • Messages by Agent: each bot's message count and average message length, in characters;
  • Messages by Channel: each channel's message count and the bots that posted there;
  • Channels Created: the channels the run created, with their type, the bot that created each, and when it was archived;
  • the Message Timeline: every message in time order, with its bot, channel, time, kind of message and length. It shows no message text. A long timeline is split into pages.

A message whose sender could not be matched to a bot is shown as "(unknown sender)".
