Staff accounts

The Staff page in the Workspace lists every manager, reviewer and admin account. A staff account has no lab bot and no research profile; the person signs in with the ORCID iD the account was created with. Managers use this page to add reviewers and to revoke, restore or delete a reviewer's access. Only an admin can change an admin or manager account.

Adding a staff account

The Add a staff account form has these fields:

  • ORCID iD: the person's iD, exactly as their ORCID record shows it (the field's placeholder shows the format).
  • Role: managers can create Reviewer accounts only. Only an admin can create a manager account.
  • Name (only if ORCID shows none): leave it blank unless the person's public ORCID record shows no name. A new account takes its name from ORCID whenever ORCID has one; a converted account keeps the name it already has, unless that name is empty or is only the ORCID iD. In those cases, and for a new person whose ORCID record shows no name, Preview says "This ORCID record shows no public name. Enter the person's name and try again." and the account takes the name you type.
{{ figure(request, "staff-form", "The Add a staff account form on the Staff page.") }}

Press Preview. Nothing is created yet: the page shows a Confirm box saying who the iD belongs to and what will happen.

  • For a new person it reads "Create a reviewer account for …", with the institution (when ORCID lists one) and the ORCID iD, followed by the current employment listed on ORCID (or "ORCID lists no current employment."). Check that this is the person you meant.
  • If the iD already belongs to a PI account, the box offers to convert it instead: "Convert …'s existing PI account … to a reviewer account", showing that account's access and whether it has a profile.

If an admin has already approved that ORCID iD for access, Preview says "That ORCID iD already belongs to an account. Ask an admin to change it." even when the person has no account yet; ask an admin to create it.

Then press Create account or Convert account to go ahead, or Cancel to leave without changing anything. A successful create shows "Created a reviewer account for …"; a successful convert shows "…'s account is now a reviewer account."

{{ figure(request, "staff-preview", "The Confirm box a preview shows before anything is created.") }} {% call careful() %}

Create account and Convert account make a reviewer account with access already approved: the person can sign in straight away, and the change is listed under Recent changes. Neither can be undone from the page. Until the person has signed in, the only way to take access away is Delete on the account's row; Revoke appears once they have signed in. For a converted account, Delete removes the person's account entirely; it does not make it a PI account again.

Converting a PI account

A manager can convert a PI account only while that account's access is still pending and it has no research profile. The account must also not be linked to a lab agent, and must have no profile or enrichment work running. If such work is running, the page says "That account has profile or enrichment work running. Try again when it finishes." When the account cannot be converted by a manager for any of the other reasons, the page says "That ORCID iD already belongs to an account. Ask an admin to change it." Then ask an admin.

Some accounts cannot be converted from this page at all, for example an existing staff account or a PI account whose access was revoked. The page then says "That ORCID iD already belongs to an account that cannot be converted here."

Other messages the Staff page can show are explained in Troubleshooting.

"Something changed since the preview"

When you confirm, every check runs again. If anything the preview showed has changed in the meantime, for example the ORCID record or the account's access, nothing is created. The page shows "Something changed since the preview. Review it again before confirming." with a fresh Confirm box. Read it again, then confirm or cancel.

Revoking, restoring and deleting access

The Accounts table lists each staff account with its Name, ORCID, Role, Access (approved, pending or revoked), Last sign-in (a date, or "never") and Actions. Your own row is marked "(you)".

The action buttons appear only on reviewer rows, and never on your own. Admin and manager rows show "—": only an admin can change those accounts.

Revoke

Revoke appears on a reviewer whose access is approved. Your browser asks you to confirm: "Revoke …'s access? They are signed out everywhere and cannot sign in until restored." The page then shows "Reviewer access revoked; they are signed out everywhere."

A manager can revoke only a reviewer who has signed in at least once. For a reviewer whose Last sign-in says "never", the Revoke button is not shown: delete the unused account instead, or ask an admin.

{% call careful() %}

Revoke takes effect at once. The reviewer is signed out on every device and cannot sign in again; they see a page saying their access has been turned off. You can give access back with Restore.

{% endcall %}

Restore

Restore appears on a reviewer whose access is revoked. It gives them access again, with no confirmation step; they sign in again as usual. The page shows "Reviewer access restored."

{% call careful() %}

Restore gives the reviewer access again at once, with no confirmation step. To take it away again, use Revoke (offered only to a reviewer who has signed in).

{% endcall %}

Delete

Delete appears on every reviewer row except your own, unless the account holds research data (a researcher profile, publications or a lab agent). That row says "Holds research data: an admin deletes it" instead, and only an admin can delete it. Your browser asks you to confirm, and the dialog says what deletion does: "Removed: the account, its review assignments, its assessment-chat history and its ORCID iD on the access allowlist." and "Kept: its reviews and approve/disapprove history, with the name …". The page then shows "Reviewer account deleted."

{% call careful() %}

Delete is permanent. The reviewer's reviews and approve/disapprove history stay, under their name; their review assignments and assessment-chat history are gone. The UI cannot undo a delete. If you only want to stop someone signing in, use Revoke, which Restore can undo. Revoke is offered only once the reviewer has signed in.

{% endcall %}

Telling a new staff member

Blackbird sends no email or other notification when you create or convert an account. Tell the person yourself:

  • to go to this site's address and sign in with ORCID, using the ORCID iD the account was created with. Signing in with any other iD lands them on an access-pending page instead (see Signing in);
  • then to open the Help tab, which has a tutorial for their role. For a reviewer that is the Reviewer tutorial.

Recent changes

The Recent changes list at the bottom of the Staff page shows the newest staff-account changes, newest first. Each line gives the time, what happened (Created, Converted from PI, Access revoked, Access restored or Deleted), the account's name, ORCID iD and role, and who made the change. If the person who made the change no longer has an account, it reads "by a deleted account".

{% call note() %}

The list records changes made on the Staff page, by managers and admins alike. Only the newest changes are shown.
