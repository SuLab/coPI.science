Prompt suggestions

The Prompt Suggestions page in the Workspace holds suggested changes to the prompts the simulation's bots work from. A bot drafts each suggestion from reviewers' feedback; people decide what, if anything, to do with it. Reviewers cannot see this page.

What suggestions are

When a reviewer records feedback on an assessment and chooses Learn, that feedback becomes eligible for analysis (see Recording a review). Feedback marked "Don't learn — log only" never is. Choosing Learn does not create a suggestion by itself: suggestions are made only when a manager or admin presses the generate button described below.

Each analysis reads the eligible feedback on one assessment, together with the interview and the current prompt files, and drafts one or more suggestions. Each suggestion names a Target, the prompt it is about, shown as scout_hub (BlackbirdBot, the hub), pi_lab (the lab agents), specialist: followed by a specialist's domain, rubric, or out_of_scope. out_of_scope means the analysis found nothing in the prompts or rubric it could fix, or its reply could not be read; the suggestion's page then still shows what the model said.

{% call note() %}

Nothing ever edits a prompt file automatically. A suggestion is text for people to read; changing a prompt is a separate, deliberate step outside Blackbird's pages.

The list shows each suggestion's Created time, Subject (the assessment it came from; click it to open the suggestion), Target and Status, newest first. Use the Status: selector (All, Open, Dismissed, Implemented) and Apply to narrow it. When there are more suggestions than the page displays, a line above the list says so; narrow by status to reach the rest. "(assessment no longer available)" means the assessment the suggestion came from has since been removed; the suggestion itself is kept.

Generating suggestions

Press Generate suggestions from current reviews at the top of the page. The line under the button says how many assessments have review feedback marked Learn that no suggestion has consumed yet. When there is none it reads "Nothing to analyse" and the button is disabled.

  • One press queues analysis for a limited number of assessments, those with the oldest feedback first. When more are waiting, the line under the button says how many one press analyses; press again for the rest.
  • The analyses run in the background. After a press, the page says how many of the eligible assessments it queued; refresh it after a minute to see new suggestions. An assessment already queued for analysis is skipped, so pressing again while earlier work is waiting queues nothing twice.
  • Once an analysis has used a piece of feedback, that feedback no longer counts as waiting. If the reviewer later edits it, it becomes eligible again.

  • While an admin is viewing the site as someone else, the button is not shown.

Each press starts real model work on the queued assessments, which costs money and cannot be cancelled from the page. It never changes a prompt file.

Status: Open, Dismissed, Implemented

Every suggestion starts as Open. On a suggestion's page, the buttons Reopen (back to Open), Dismiss and Mark Implemented set its status. Next to them the page shows who last set the status and when.

The status is a record for people only: it says what someone decided about the suggestion. Marking a suggestion Implemented does not apply it, and Dismiss does not delete it. Use Mark Implemented once the change has actually been made to the prompts.

{% call careful() %}

Setting a status records your name and the time on the suggestion, for everyone with access to this page to see. Any status can be changed again with another button.

{% endcall %}

A suggestion's page

Click a suggestion's Subject to open it. Its heading is the assessment it came from, and the line under it gives the Target, the model that drafted it, when it was created and, when recorded, the rubric version. These warnings can appear there: "no interview transcript" (the interview could not be found, so the analysis worked without it) and "input truncated" (the interview was too long, so the analysis read only part of it).

{{ figure(request, "prompt-suggestion-detail", "A suggestion's page: the status buttons, the suggested change and where it came from.") }}
  • Suggested Change: the drafted change, in the bot's words. Open Raw model response to see the full reply it came from.
  • Distilled From: the review feedback the suggestion was drafted from, one row per piece of feedback, with the Reviewer, the overall Score (out of 5), the Mode, the Comment and When it was first written.
  • Prompt Files Read: every prompt file the analysis read, each with a badge comparing it with the file as it is now:
    • current: the file is unchanged since the suggestion was drafted;
    • STALE: the file has changed since then, so the suggestion may describe text that is no longer there. Read it against the current file;
    • file missing: the file no longer exists, or the analysis could not read it at the time.
