What it means

The Account card

It shows the PI's email, ORCID, institution and department, and:

  • Verified with a date, or Unverified beside the email. An unverified address offers Mark verified. Blackbird sends no verification email: the button records that you vouch for the address.
  • A Name note when the name was cleaned from its ORCID form, asking you to check the spelling.
  • Onboarding Complete: Yes once the PI has saved their own profile in Blackbird's onboarding pages. A PI who never signed in shows No.
  • Claimed At: when the PI first signed in to an account that already existed (such as one Add PI created), or Unclaimed.
  • Joined: when the account was created.
{% call careful("Careful: Mark verified") %}

Mark verified stamps the address as verified and records that you vouched for it. There is no button to unverify; changing the address clears the stamp.

{% endcall %}

Edit Profile

The form appears once the PI has a profile; before that the page says The Edit Profile form appears once the profile exists. It holds the display name, email, institution, department, Research Summary, the profile's keyword lists and JHU tenure start (year).

The tenure year decides which publications ground the profile and the lab bot's publication list: those from that year on. A recorded year always wins and is never worked out again. Without one, Blackbird takes it from a current Hopkins position on ORCID, else from the earliest ORCID-confirmed paper on which the PI's own affiliation is Hopkins; a year taken from papers is provisional when ORCID could not be read or the search was incomplete, and a note under the field names it. Leaving the field blank leaves it unchanged. A PI with no year, recorded or provisional, is treated as full career for the profile, the persona, the PI page's list and the grants, and has no industry score. A PI with only a few papers from that year on is treated as full career for the profile and persona; with a recorded year the PI page's own list stays limited to the window.

{% call careful("Careful: Save Changes") %}

Save Changes writes a new profile version and updates the persona the lab bot works from. A name change also renames the lab bot in the simulation, but not the Slack app's display name. A changed tenure year also queues a profile regeneration. Once the profile text has been edited, later regenerations arrive as a draft to review instead of overwriting it. To undo a save, edit and save again.

{% endcall %}

Regenerate profile and Retry profile generation

Regenerate profile, at the top of the Corpus and profile review card, queues a new generation for any PI. It is disabled, with its reason printed under it, while a generation is queued or running and for a while after one finishes. Retry profile generation appears only in the header of a PI whose lab bot is still pending, and only when generation failed or produced no usable profile.

{% call careful("Careful: Regenerate and Retry") %}

Both queue a profile generation, which runs in the background and cannot be cancelled from the page. Every generation re-reads the ORCID fundings, and every generation that completes also refreshes the grants and industry evidence and runs company discovery again. If the stored profile passed the quality checks, a new text that fails them twice, or is written from no abstracts while the stored one had some, is thrown away and the stored profile stays unchanged; if the stored profile had failed them, the new text replaces it anyway. A profile a person edited gets a Pending draft instead.

{% endcall %}

Pending draft

A regeneration of an edited profile is staged as a Pending draft, listing each field that differs as Stored and Draft, and marked when it failed the quality checks. Accept draft writes it into the profile; Discard draft drops it. If the profile changed after the draft was made, only Discard is offered and the card says The profile changed since this draft was made; discard it or regenerate.

{% call careful("Careful: Accept or Discard draft") %}

Accept draft replaces the stored profile fields with the draft's and updates the persona. Discard draft deletes the draft. Neither can be undone from the page.

{% endcall %}

Candidate, unanchored and excluded papers

  • Candidate papers were found only by OpenAlex or the name search, with no ORCID anchor. Accept fetches the paper from PubMed and stores it; Reject sets it aside.
  • Unanchored papers are stored papers no ORCID anchor confirms. Keep marks one as checked: the paper stays in the profile, leaves this list and is no longer offered for Exclude; Exclude removes it from the profile and the persona. Only papers on this list can be excluded from the page: a paper confirmed by ORCID, or a work stored without a PubMed record, has no Exclude button.
  • Excluded papers, under a disclosure, list every excluded paper with Restore, which brings it back.
{% call careful("Careful: paper decisions") %}

Accept adds the paper to the PI's corpus and updates the persona; no button removes it again. A rejected candidate is not offered again, but a later generation stores it if the PI's ORCID record or PubMed's ORCID field confirms it. Keep is permanent: a kept paper is no longer offered for Exclude. Exclude takes the paper out of the profile and the persona; Restore undoes it.

{% endcall %}

The persona file and its revisions

The persona is the profile text the PI's lab bot works from. When the saved persona no longer matches what the profile would produce, or its last write failed, the card says Persona file out of date and offers Re-export, which writes it again. The Persona revisions card lists the newest revisions, newest first: when, how it was changed, by whom, and the full text under view text.

{% call careful("Careful: Re-export") %}

Re-export rewrites the persona from the current profile and records a revision. It changes nothing in the profile itself.

{% endcall %}

Jobs

The Jobs table at the bottom lists the background work run for this PI: its type, status (Pending, Processing, Completed or Dead; a job whose attempt failed waits as Pending until it is retried), attempts, and when it was queued and completed. A job that failed shows the start of its error under its row.
