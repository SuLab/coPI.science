What it means

The columns

Each PI's name opens their page. Some columns appear only on wider screens. Reviewers see only Name, Institution, ORCID, Pubs (tenure) and Industry interest; the rest are for managers and admins.

  • Status is the research profile's state: No Profile (no profile with a research summary yet; a PI's first generation can still be running), Generating (a profile generation is queued or running and the profile has no summary yet), Complete (the profile has a research summary) and Pending draft (a regenerated draft is waiting for a manager to accept or discard it).
  • Agent is the PI's lab bot: Not requested (the PI has an account but no lab bot, for example a PI who signed in with ORCID before anyone added them), Pending (created but not yet live, whether or not its Slack bot is installed), Active (taking part in the simulation), Muted (taken off the simulation by a manager's Mute or by an admin) and Suspended (only an admin can manage a suspended bot).
  • Pubs (tenure) counts publications from the PI's JHU tenure start on. A full career tag means no tenure start is recorded, so every publication counts; an undated note counts papers left out because they have no year.
  • Industry interest is the PI's cohort percentile. A manager may instead see rescoring, unscored or a dash, and partial when some evidence sources were unavailable.
  • Version is the profile's version number, which rises with every saved change.
  • Claimed shows when the PI first signed in to an account that already existed (such as one Add PI created), or No.
  • Joined and Last Login are when the account was created and when the PI last signed in.

Filters

Profile Status narrows the list to one of the statuses above, and Claimed to PIs who have or have not signed in. Apply runs them.

The Add PI form

The form at the top takes Add a PI by ORCID iD and, only when the ORCID record shows no public name, Name (only if ORCID shows none). The line under it is a reminder: managers and reviewers are added on the Staff page, because Add PI always creates a lab bot.

{% call careful("Careful: Add PI") %}

Add PI creates a real PI account from the ORCID record (or, for a PI who already signed in and has no lab bot, adopts that account), queues their profile generation and creates their lab bot in the Pending state. The bot's persona is published as soon as the PI has a profile. Add PI then opens the new PI's page. Nothing in the Workspace undoes it: only an admin can delete a PI's account.

{% endcall %}

When Add PI is refused, a message beside the button says why. For example: the iD is malformed, a user with that ORCID already exists, the ORCID record could not be fetched, the record shows no public name, or the name entered has characters a name may not contain.
