What it means

The Staff page lists every manager, reviewer and admin account. A staff account has no lab bot and no research profile; the person signs in with the account's ORCID iD. A manager can add reviewer accounts only, and only an admin can change an admin or manager account.

Preview, then Confirm

Add a staff account takes an ORCID iD, a Role (for a manager, only Reviewer) and, only when the ORCID record shows no public name, Name (only if ORCID shows none). Preview creates nothing. It shows a Confirm box saying who the iD belongs to:

  • for a new person, the name and institution from their public ORCID record and their current employment, with Create account;
  • for someone who already has a PI account that may be converted, that account's access and whether it has a profile, with Convert account.

Cancel drops the preview. If anything shown changed before you confirm, the box comes back with Something changed since the preview. Review it again before confirming. and nothing is written.

A manager is told That ORCID iD already belongs to an account. Ask an admin to change it. when the iD belongs to a PI account that has a lab bot, helps run one as a delegate, has a profile or already has approved access, and when an admin has pre-approved the iD on the access allowlist. Other refusals each say why in their own message.

{% call careful("Careful: Create account and Convert account") %}

Create account makes a reviewer account whose access is already approved, so the person can sign in at once. Convert account turns the existing PI account into a reviewer account with approved access. Both are listed under Recent changes. Neither can be undone from the page: Delete removes the account entirely (for a converted account, the person's former PI account too); Revoke becomes available once the person has signed in.

{% endcall %}

The Accounts table

Each row shows the name, ORCID iD, role, Access (approved, pending or revoked) and Last sign-in (a date or never). The actions appear only on reviewer rows, never on your own:

  • Revoke turns off a reviewer's access. A manager can revoke only a reviewer who has signed in at least once; for one who never has, Revoke is not offered, and the choice is to delete the unused account or ask an admin.
  • Restore gives a revoked reviewer access again.
  • Delete removes a reviewer account.
{% call careful("Careful: Revoke and Restore") %}

Revoke asks first, then signs the reviewer out everywhere; they cannot sign in until restored. Restore undoes it, but the reviewer has to sign in again.

{% endcall %} {% call careful("Careful: Delete") %}

Delete asks first. The reviewer's reviews and approve/disapprove history are kept, with their name. Their review assignments and their assessment-chat history are deleted, and the ORCID iD is removed from the access allowlist. It cannot be undone.

{% endcall %}

Telling the new reviewer

Blackbird sends no notification when an account is created or converted. The person learns of it only from you: they go to this site's address and sign in with ORCID using the iD the account was created with (signing in with any other iD lands them on an access-pending page instead), land in the Workspace, and find their tutorial under Help.

Recent changes

The last section lists the newest staff account changes: Created, Converted from PI, Access revoked, Access restored and Deleted, each with who made it and when.
