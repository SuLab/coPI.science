What it means

A PI goes from being added to having a live lab bot in this order. Each stage below names what the PI's page shows.

Added

Add PI on the PIs page creates the account, queues a profile generation and creates a lab bot in the Pending state. When the ORCID record lists employment that gives a JHU tenure start, that year is recorded too.

{% call careful("Careful: Add PI") %}

Add PI creates a real PI account and queues work for it at once. Nothing in the Workspace undoes it: only an admin can delete a PI's account.

{% endcall %}

Profile generation

The profile is generated in the background from the PI's publications. While it runs, the header says Agent pending — Profile generating…, and the page shows the change when it is reloaded. When generation failed, when no profile exists yet, or when the profile is not grounded in any publication abstract, the header says so in red and offers Retry profile generation, which queues the generation again. The step Reviewing a PI's profile covers the profile itself.

{% call careful("Careful: Retry profile generation") %}

Retry queues a full profile generation, which runs in the background and cannot be cancelled from the page.

{% endcall %}

Install Slack bot

With the profile done, the header says Agent pending — Awaiting Slack install. It keeps saying so after the install; the button below it shows the real next step. Until the bot is installed the button is Install Slack bot, which creates this PI's Slack app and takes you to Slack's install screen. When Slack sends you back, the PI's page says Slack bot installed — the token is saved on this PI's agent. Activate the agent to bring it live. If it fails, a message starting Slack provisioning failed says why: on the PI's page, or on the PIs list when the install failed or was cancelled in Slack.

{% call careful("Careful: Install Slack bot") %}

Install Slack bot creates a real Slack app for this PI's lab bot and starts Slack's install. Nothing in the Workspace removes the app again.

{% endcall %}

Activate agent

Once the Slack bot is installed, the button becomes Activate agent. Activating first runs a check. A profile or persona problem refuses it with a red box headed Activation refused — this PI's profile is not ready: that lists each reason; a lab that cannot be connected to the hub is refused with a message starting Activation refused: instead. The check refuses a lab bot when:

  • the PI has no profile, or it is not grounded in any publication abstract, or it has no Research Summary;
  • the newest profile generation failed for good;
  • the persona the simulation reads is missing or has no Research Summary;
  • the account is not a PI account;
  • the lab could not be connected to the hub.

There is no override for managers. Only an admin can override the profile checks; nobody can override the persona, account or hub checks. The refusal box itself names the way forward: retrying the profile generation, fixing the profile, or asking an admin.

On success a green box says Agent activated — the running simulation picks it up on its next roster sync, and the box itself says how soon that is.

{% call careful("Careful: Activate agent") %}

Activate puts the lab bot on the live roster: a running simulation picks it up at its next roster sync and the bot starts taking part in Slack. To take it back off, use Mute.

{% endcall %}

Mute and Unmute

An active lab bot shows Mute. Muting takes it off the simulation, and the header then shows Unmute and, after a manager's mute, when it was muted. Muted also covers a bot an admin has parked; Unmute works on both.

Unmute runs the same activation check again, and also needs the Slack bot to be installed and the lab to connect to the hub. When it is refused, a red box at the top of the page says which of these failed.

{% call careful("Careful: Mute and Unmute") %}

Mute takes the lab bot off a running simulation at its next roster sync; Unmute puts it back. Each undoes the other.

{% endcall %}

Mute is offered only for an active or muted bot. A suspended bot shows its status instead, and only an admin can manage it. The same controls appear on the Slack Bots page (the step The Slack Bots page).
