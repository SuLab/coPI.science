## Adversarial pass — four attacks on my own draft, three of which changed it

**A1. "Hoist `ssl.create_default_context(cafile=certifi.where())`" — rejected as written.**
A hand-rolled context can drift from httpx's defaults and silently weaken TLS. httpx
**0.28.1** exposes `httpx.create_ssl_context()`; I compared both and they match exactly
(`check_hostname=True`, `verify_mode=2`, `minimum_version=MINIMUM_SUPPORTED`). Use
httpx's own, so it cannot drift. Measured effect: **33.40 ms → 0.15 ms** per client, and a
shared context is not an asyncio object — verified usable from two successive fresh event
loops, so it does not reintroduce the loop-affinity bug Task 23 fixed for the semaphore.

**A2. "Revert the interval to 0.12" — rejected; it breaks a test that closes a filed item.**
`tests/contract/test_pubmed_contract.py::test_ncbi_pacing_lands_at_the_policy_ceiling_not_below_it`
asserts `9.5 <= keyed_rate <= 10.0`. At 0.12 the rate is 8.33 and that test fails — and it
exists to close **over-impl R4 / closure-23 R2**, a filed issue item saying the 0.12 pacing
threw away 17 % of the granted ceiling. So the two findings genuinely conflict on one knob.

Resolved by fixing the **invariant**, not the number. The average rate was the wrong thing
to pin — it is exactly why this defect passed that test. The property NCBI enforces is
**arrivals per second**, whose worst case is `floor(1/iv) + 1`. To hold that at 9 (one
request of margin) we need `iv > 1/9 = 0.1111`. So: **`0.112`** → average **8.93 req/s
(89.3 % of the ceiling)**, worst-case burst **9**. That keeps R4's substance (89 % beats
83 %) while restoring the margin D5 showed 0.105 had spent. The test is amended to pin the
**burst bound** as well as the average, because the burst is the invariant that matters.

**A3. `create_revision` dedups on content.** `profile_versioning.py:87` is
`if previous is not None and previous.content == content`. Recording `stripped` therefore
means a second whitespace-only clear dedups instead of writing a second row. Harmless for
the guard — the first empty revision persists, which is all it looks for — but it must be
stated, not discovered later.

**A4. No data fix is needed.** I expected legacy rows recorded with raw whitespace outside
`btrim`'s set. There are **none** (0 of 35). D3 is forward-only.

## D5 — the plan

1. Module-level `_NCBI_SSL_CONTEXT = httpx.create_ssl_context()`, passed as `verify=` at
   `pubmed.py:221`. Comment records the 31.9 ms measurement and *why* a loop block defeats
   `_pace_ncbi`: the gate can only delay a start relative to a loop that is running, so
   every reservation that came due during the stall departs in the same tick.
2. `_NCBI_PACING_SECONDS[True] = 0.105 → 0.112`, with the burst arithmetic in the comment.
3. Correct the false claim at `pubmed.py:126-136` ("the achieved rate is always
   <= 1/interval … never over it"). The reservation *schedule* is bounded; *departures* are
   not. The same sentence is repeated in `task-23.md` and must be corrected there too.
4. Tests, each proven red against the current source:
   - a **burst** test: N concurrent `_ncbi_get` calls never start more than 9 in any
     sliding 1 s window. Driven with the real client-construction path (a mocked transport
     still builds the client, which is the point) and a monotonic clock recorder, asserting
     on the **count in a window**, not on a wall-clock threshold, so it cannot flake.
   - an **arithmetic** pin: `floor(1/interval) + 1 <= 9` for the keyed path and `<= 3` for
     the keyless one.
   - the mutant the audit found surviving: **releasing the slot before the request** must
     turn a test red. Assert peak in-flight `<= 8` via `attempt_context` instrumentation.

## D3 — the plan

1. `agent_page.py:1636`: record `stripped`, not `content`. The route already computes it at
   `:1609` and already stores it as `private_profile_md`, so the revision currently
   disagrees with the profile it is a version of.
2. Make the guard's emptiness test **Python-side** over the agent's own private revisions
   rather than trusting a spelled-out SQL character class. 35 private revisions exist in
   the whole production copy, so this is a handful of rows per agent. `str.strip()` is
   Unicode-aware by definition, so it cannot fall behind a new code point — enumerating
   `btrim` characters is the whack-a-mole this defect *is*.
3. Delete the false premise at `:669-672` ("Whitespace a browser can actually submit in a
   textarea") — a textarea can submit any Unicode whitespace.
4. Update the GM test docstring at `test_profile_pipeline_gm.py:1182-1185`, which explains
   the whitespace fixture by saying "the route records the RAW submitted body". After (1)
   that is no longer true; the fixture stays valid as a *legacy* row.
5. Tests: all 7 disagreeing code points, end to end through the real route and the real
   `run_profile_pipeline`, asserting no seed is regenerated and no file is rewritten.
