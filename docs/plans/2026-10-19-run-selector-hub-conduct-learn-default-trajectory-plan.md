# Run bar, hub conduct rule, Learn default, interview trajectories — Implementation Plan

> **For agentic workers:** execute with `/lathe:plan-execution`: Tasks 1-9 are disjoint-file
> packages implemented in parallel with **no build and no test run**; Task 10 is the single
> integrated build-and-test pass after merge; Task 11 is owner-gated release work. Steps use
> checkbox (`- [ ]`) syntax. Implementers do not run the "Run" steps; the lead runs them in
> Task 10.

**Goal:** Ship the four changes of the approved design: a bordered run bar on Assessments,
Discussions and a new Interviews page; a hub prompt rule (scout_hub 1.12.0 plus all eight
specialist personas) that stops BlackbirdBot judging the lab agent's conduct; Learn as the
default feedback mode; and a staff-only Interviews page with one model-written line per post.

**Architecture:** Server-rendered FastAPI + Jinja pages whose context passes through the
allowlist projection in `src/web/presentation.py`; services return plain dicts. Model lines
are generated by the worker's idle loop on the `assessment_chat_suggestions` pattern and
stored in a new run-scoped table `interview_trajectories` (migration `0072`). The prompt
change is prompt files only.

**Tech Stack:** Python 3.11, FastAPI, SQLAlchemy 2 async, Alembic, Postgres 15, Jinja2,
Tailwind 3.4.19 (compiled, `scripts/build_css.sh`), Anthropic SDK via `src/services/llm.py`,
pytest + syrupy.

**Spec:** `docs/specs/2026-10-19-run-selector-hub-conduct-learn-default-trajectory-design.md`
(approved 2026-10-19; decisions D1-D8 in its §6). Read it with this plan.

## As built (amendments recorded 2026-10-19, after integration and the adversarial audit)

- **Review Focus 1 narrowed.** The worker already loaded `blackbird_rubric` and
  `rubric_revisions` before this change (through `assessment_chat_suggestions` →
  `assessment_chat`), and `trajectory_generation` reuses `assessment_chat`'s helpers, so
  the test is `test_interview_posts_import_chain_avoids_the_rubric`: the module the page
  and the worker share stays clear of both. No new runtime exposure.
- **Outcome order.** "Verdict dropped" wins over the plain "Closed" fallback (the plan's
  first-match order made it unreachable whenever a decision existed); every label is
  tested.
- **Item 11 wording.** "a fact about the team or market, never how the lab agent behaved
  in this interview — never a bare topic heading": "the team's record" was dropped because
  Principle 8 counts a named team member as a fact about the work (spec §2.4b updated).
- **Sidecar preamble placement.** The two sentences sit before "Everything below must be
  captured here in full:", which keeps the colon introducing the list.
- **Trajectory cost.** One attempt is reserved at its own worst case
  (`attempt_reserve`, about $0.28 on claude-opus-5), not the chat's $2.50; a result that
  cannot be stored is logged by type only; an interview whose posts cannot be built is
  skipped, not retried every sweep; a bare `<` or `>` in a line is kept.
- **Re-verification.** The generator re-reads an interview's posts when the stored hash or
  the thread's post-row signature (row count, newest `created_at`) changes.
- **Interviews page.** A recorded hub decline links to the Assessments page's declines
  list; a note says lines are model-written; the page reads `left(content, 600)`.
- **Discussions count** includes orphan threads (decisions whose root post is gone).
- **Replay script.** `CONDUCT_RE` also matches "concession"; PASS needs every replay
  parsed; REVIEW exits 1; output is written outside the checkout (and git-ignored).
- **Repair script.** `ended_at` is the later of the newest LLM call and the newest message.
- **Freeze suite.** Regenerated with `ENGINE_REFUSAL_FALLBACK_ENABLED=false`: the host's
  `.env` turns the engine fallback on, which changes three pi_lab entries that D1 does not
  license. The seven licensed entries are the only ones that change.
